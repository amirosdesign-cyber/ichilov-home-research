# Ichilov HOME — הכנה לחיבור הטבלה והמייל

**סטטוס: הכנה בלבד; לא מחובר לאתר הציבורי ולא קולט תשובות אמת.**

## מה כבר קיים

- אתר GitHub Pages עם ארבעה מסלולים: קצר/עומק × מטופל/משפחה
- Google Sheets עם ארבע לשוניות תואמות
- ייצוא CSV מקומי מהאתר

## למה לא מחברים ישירות ל-GitHub Pages?

כל JavaScript בדף ציבורי נגיש למבקרים. מפתח גישה שמוטמע בו אינו סוד.
Google Apps Script אינו מספק מעצמו מנגנון אימות/CORS מתאים לקליטה
מאובטחת וישירה מכל דפדפן. לכן אסור לפרסם מפתח קליטה או הרשאות חשבון
בתוך index.html. הכתובת של Apps Script לבדה גם אינה מהווה הגנה.

## איך מחברים בהמשך (אחרי אישור בית החולים)

1. לוודא שהגיוס, ההסכמה, סוגי המידע, שמירתו והגורם המארח אושרו.
2. לבחור שירות קליטה/Proxy מאובטח, עם הגבלת בקשות, לוגים ללא פרטים רפואיים,
   אימות בצד השרת ויכולת ניטור ותקלות.
3. ליצור פרויקט Google Apps Script בבעלות חשבון מחקר מאושר ולהדביק Code.gs.
4. להגדיר **Script Properties** (ולא בקוד ציבורי):
   - `SPREADSHEET_ID`: מזהה הטבלה המורשית
   - `NOTIFY_EMAIL`: כתובת דיווח מורשית
   - `INGEST_TOKEN`: מפתח אקראי חזק, שמור רק בשרת המתווך
5. לפרסם את הפרויקט בהתאם למדיניות ההרשאות של הארגון.
6. לפני הפעלת נתוני אמת: בדיקת נתוני דמה, בדיקת קובץ CSV,
   בדיקת קבלת הודעה במייל ובדיקת כשל והגנות.
7. לאחר אישור מפורש, לבטל את מצב 'בדיקות בלבד' בקוד,
   ורק אז להוסיף אפשרות הגשה מהאתר.

## מבנה בקשת בדיקה לשרת המאושר

```json
{
  "token": "<server-side-only>",
  "test": true,
  "mode": "short",
  "type": "patient",
  "code": "TEST-01",
  "stage": "במהלך האשפוז",
  "answers": ["בחירה ראשונה", "בחירה שנייה", "", "", "", "", "", ""]
}
```

התשובות נשמרות בטבלה, אבל המייל מכיל **התראה ומספר אסמכתה בלבד** —
ללא תוכן התשובות.

## מגבלה חשובה

הקוד הוא בסיס טכני לבדיקת דמה, לא מערכת אחסון מידע רפואי מאושרת.
אין לפרוס אותו לשימוש עם משתתפים ללא סקירת אבטחה, הרשאות מחקר,
מדיניות שמירה ומחיקה ואישור מוסדי. בטופס הציבורי נשאר ייצוא CSV בלבד.
